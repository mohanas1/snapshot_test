Full pipeline (one button)

Runs in order: refresh VM inventory (Prism + PE CVM IPs via ncli) → force disk job to Update + parallel clusters + PE stats throttle + adaptive SSH → Disk job (guest SSH; pipeline waits) → Snapshot run (waits) → Curator on PEs. While it runs, stage status and progress bars stay in the sticky strip under Actions above; each stage has an Open job link when a background job exists. Only one disk job per Prism Central is allowed at a time (server blocks a second start while one is queued or running). Individual buttons elsewhere still work as before.

Workload simulation (guest SSH / disk churn)

Eligible guests: IP in Prism inventory, powered on, configured RAM above the minimum (MiB from Prism; default >250), and not skipped by name rules. Guest SSH counts use the server inventory cache from when this page loaded (reload after changing skips). Limit how many get SSH with a number or percent (e.g. 100, 50%); leave blank for all eligible. Each run uses sshpass + ssh to the guest and runs: Delete — rm -f …*.img · Create — openssl | dd with your bs and count · Add — append · Update — overwrite · All mix — random per VM.
